# Contributing

Flutter Craft is primarily a structured learning journey. Feedback should help the learner understand the code and improve their engineering judgement.

## Helpful contributions

- Report unclear requirements or broken challenge instructions.
- Suggest useful edge cases and accessibility checks.
- Review code for correctness, readability, maintainability and tests.
- Share documentation or learning resources relevant to the current week.

## Review approach

When giving feedback:

1. Explain the underlying concept, not just the change to make.
2. Identify the smallest useful correction.
3. Distinguish a bug from a stylistic preference.
4. Avoid replacing a learner's implementation wholesale.
5. Encourage tests and verification.

## Code conventions

- Use `dart format .` before submitting Dart changes.
- Run `flutter analyze` and relevant tests in the affected app.
- Prefer clear names, small focused widgets and explicit state ownership.
- Avoid adding dependencies without explaining the need.
- Do not commit credentials, signing keys, API secrets, personal data or generated build output.

## Scope

Do not introduce real payment processing, real banking credentials or unsafe handling of personal information into the learning finance app.

## 🚀 Getting started

### Development setup

You'll need:

- Flutter SDK (stable channel) and the bundled Dart SDK
- Android Studio or another configured IDE
- An Android emulator or physical Android device
- Git

Verify your installation:

```bash
flutter --version
dart --version
flutter doctor -v
git --version
```

### Run your first project

```bash
git clone https://github.com/Markkaruga254/flutter_craft.git
cd flutter_craft/apps/01-pocket-finance
flutter pub get
flutter run
```

Each app is independently runnable and will have its own `pubspec.yaml`, source, tests, assets and project README as it is scaffolded.

## 🧪 Definition of done

A project is not complete just because the screen looks right. Aim to:

- [ ] Complete the core user journey end to end.
- [ ] Check layouts on more than one screen size.
- [ ] Handle loading, empty, error and success states where relevant.
- [ ] Give interactive controls meaningful behaviour and accessible labels.
- [ ] Format code and pass static analysis and relevant tests.
- [ ] Document setup, features and design decisions.
- [ ] Add screenshots or a short demo when ready.

## 🧠 How to learn effectively

1. **Attempt first.** Challenges are tasks, not copy-paste tutorials.
2. **Understand the error.** Read logs, use breakpoints and investigate before changing code.
3. **Build in small steps.** Commit meaningful progress instead of waiting for a perfect result.
4. **Ask focused questions.** Share the day number, relevant code, exact error and what you tried.
5. **Reflect honestly.** Record confusion and lessons in your learning log.
6. **Stay consistent.** Missing a day is not a reason to skip ahead; resume at the next unfinished challenge.

## 🧰 Suggested technology progression

Dart fundamentals → Flutter widgets and Material 3 → navigation → local persistence → state management → REST APIs → authentication and user-specific data → animation and advanced rendering → testing and release preparation.

Riverpod, Dio, go_router and other packages may be introduced when their use is justified. Understand the problem before adding a dependency.

## 🔒 Safety and scope

Pocket Finance is a learning application. Use mock data only. Do not enter real banking credentials, connect real accounts, or implement real-money transfers or payments. Other projects should use mock data and safe development practices unless a challenge explicitly establishes a secure alternative.
